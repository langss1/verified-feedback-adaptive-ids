# D5: native ARF and two unused capture members

This repository folder is the reviewable source copy. For execution, use the
canonical release ZIP and the sibling-directory layout described below; do not
run the source copy in place inside `extensions/d5`.

This is a frozen extension of the verified-feedback adaptive IDS study. It adds a
locally executed streaming Adaptive Random Forest (River 0.22.0), two previously
unscored corrected CSE-CICIDS2018 capture members, and matched label acquisition.
All feedback is simulated. This is an evaluation of established learners and an
operational integration, not a new base learning algorithm.

## Layout and setup

Use the exact sibling-directory layout below. The canonical release ZIP retains
the D5 directory name. D4 remains a read-only dependency, including its original
prepared inputs and saved traces.

```
workspace/
  adaptive_feedback_d4_20261126/     # clone of the original public repository
  adaptive_baseline_d5_20261126/     # this ZIP extracted next to that clone
```

1. Clone `https://github.com/langss1/verified-feedback-adaptive-ids` into the
   directory `adaptive_feedback_d4_20261126`.
2. In that clone, run `python download_artifacts.py --results`. This verifies and
   extracts the original v1.0.0 inputs, example models, and saved prediction ledgers.
3. Extract the D5 extension ZIP into the clone's parent workspace.
4. Use a separate Python 3.11 environment and install D5 `requirements.txt`.
   The experiment used Windows/Python 3.11.7, numpy 1.26.4, sklearn 1.9.1,
   scipy 1.17.1, River 0.22.0 and pandas 2.2.3. Data preparation used pandas 2.1.3
   for consistency with D4. Vendored dependencies are not redistributed in this ZIP.

## Audit, analyze, and replay

From the D5 directory:

```
python check_adapter.py
python audit_extension.py
python analyze_extension.py
python fresh_replay_check.py
python make_extension_figures.py
```

`check_adapter.py` reconstructs 120 original D4 verified/maximum/frozen control
traces exactly and tests audit exclusion, correction handling and determinism on
small synthetic software fixtures. Those fixtures are not experiment results.

`audit_extension.py` checks every additional system evaluation, prediction metrics,
feedback schedules, training-label uses and all original frozen D4 input/source
hashes. `fresh_replay_check.py` rebuilds source models and reruns one Hulk16,
seed-11 corrected-feedback case, checking exact GDT/ARF target and source outputs.
This validates one replay case, not universal correctness.

`run_extension.py --workers 5` validates the freeze and resumes missing cases. It
skips case CSVs that already exist. For a complete independent rerun, use a NEW
workspace with the same directory layout, D4 dependency and D5 source, protocol,
data, cache and checks, but without copied result case files. Keep the supplied
source-training caches when validating the original byte-level lock. Rebuilding
caches can change pickle metadata/timing bytes even when model predictions agree;
do not overwrite or silently replace the archived lock.

To recreate the input cohorts from author CSVs, `prepare_new.py --dataset dos16_new`
and `--dataset ddos20_new` stream the predeclared members from the pinned author
archive. They also require the original corrected CICIDS2017 ZIP under
`workspace/dual_verifier_d2_20261125/data/CICIDS2017_improved.zip` to reconstruct
historical exclusion fingerprints. Prepared arrays and member acquisition receipts
are included, so downloading the large source archives is unnecessary for replay.

## Interpretation

- The original 870-run archive is unchanged. D5 adds 80 ARF runs and 40 shared
  HGB/NN trajectories, yielding 240 additional system evaluations. Reusing 160
  original system evaluations produces a 400-row comparison matrix. The rows
  are correlated; they are not 400 independent networks or training replicates.
- New samples contain 12,000 flows each: Hulk16 has 3,920 attacks and DDoS20 has
  843 attacks. Sampling is label-blind after deduplication and overlap filtering.
  These are unused historical capture members, not 2026 production traffic.
- No predictor fingerprints overlap the earlier sampled 2018 cohorts. The two new
  samples share 63 fingerprints and the same benchmark/testbed. A clearly labeled
  post-hoc sensitivity removes those fingerprints from evaluation only; it does
  not erase their previous training influence or create independent sites.
- Requests, delivered labels/revisions, training/audit roles and threshold rules
  are exactly shared. Acquisition is generated by the frozen HGB/7NN policy;
  the ARF comparison does not test ARF-specific active acquisition.
- Native ARF uses library defaults, one unweighted update per arrived training
  label at 100-flow boundaries, and initial-state restoration/replay on a changed
  learned label. HGB uses 1/4/8 weights, bounded replay and 200-flow regular refits.
  Do not claim identical memory, weighting, computation or pure learner-only
  causal attribution. The cleaner gate comparison remains matched verified-only.
- Primary metrics use issued threshold-shifted decision scores. Raw-score metrics
  are supplied separately. Neither is claimed to be a calibrated posterior.
- Five-seed paired intervals describe algorithmic variation. They are unadjusted
  and do not establish multi-organization generalization. All failed criteria and
  stronger simple controls must remain visible.

Read `analysis/verdict.json`, `analysis/summary.csv`, the paired comparison CSV,
the complete per-condition/family tables, and the PDF supplement for results.
No model was retuned or replaced using the new capture outcomes.
